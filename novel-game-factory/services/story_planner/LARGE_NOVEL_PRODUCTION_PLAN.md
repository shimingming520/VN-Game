# 40–60 万字小说上线优化清单

按风险从高到低逐项实施；每项独立完成测试、提交和远端推送后再进入下一项。

| 序号 | 优化项 | 当前状态 |
| --- | --- | --- |
| 1 | 全链路超时：LLM、Celery 软硬超时、Redis visibility、阶段等待、人工确认 | 已完成 |
| 2 | 大文本预检：字数、章节数、预计调用量、预计耗时和异常输入拦截 | 已完成 |
| 3 | 超长章节切分与分层摘要，避免单次上下文过大 | 已完成 |
| 4 | 各阶段 Token/上下文预算和提示词裁剪 | 已完成 |
| 5 | 网络重试、指数退避、限流和错误分类 | 已完成 |
| 6 | 节点级断点续跑和失败节点单独重生成 | 已完成 |
| 7 | 缓存版本、失效策略、共享存储和命中统计 | 已完成 |
| 8 | 有界并发、全局速率限制和背压 | 已完成 |
| 9 | 幂等、数据库事务、重复投递和重跑清理 | 已完成 |
| 10 | 输出完整性、剧情质量和发布前门禁 | 已完成 |
| 11 | 结构化日志、心跳、阶段耗时和卡死检测 | 已完成 |
| 12 | 40–60 万字压力测试、容量基线和上线验收 | 待处理 |

## 第 1 项验收值

- K8s LLM 单请求超时：1800 秒（30 分钟）。
- story_planner 自身运行时兜底：软超时 136800 秒（38 小时），硬超时 172800 秒（48 小时）。
- 合并主分支后的共享 Celery 生产保护：软超时 171600 秒（47 小时 40 分），
  硬超时 172800 秒（48 小时）；共享规则优先于任务兜底。
- Redis broker visibility timeout：1209600 秒（14 天）。
- 重复任务阶段等待：174600 秒（48 小时 30 分）。
- 世界观/大纲人工确认：21600 秒（6 小时）。
- Celery worker 启动时显式开启 broker 重试。

## 第 2 项验收值

- 默认最大输入：1500000 字符；可通过 `STORY_PLANNER_MAX_NOVEL_CHARS` 调整。
- 默认最大章节数：3000；可通过 `STORY_PLANNER_MAX_CHAPTERS` 调整。
- 40–60 万字属于正常大文本范围，只记录长任务警告，不拒绝。
- 解码替换字符超过全文 1% 时拒绝，避免乱码进入昂贵 LLM 流程。
- original 与 chapter_branch 都在首次数据库正文写入/LLM 分析前执行预检。
- 报告包含字符、UTF-8 字节、章节均值/最大值、世界观分段、章节摘要分段、
  输出节点、软分支、LLM 调用和耗时区间。
- 调用耗时基线默认 30 秒/次，可通过
  `STORY_PLANNER_ESTIMATED_LLM_SECONDS_PER_CALL` 调整；报告为容量规划估算，
  实际耗时仍受重试、网关负载和内容质量门禁影响。

## 第 3 项验收值

- 超长章节分析段默认上限：13000 字符。
- 章节摘要分层归并每批默认最多：8 份。
- 世界观分析段默认上限：50000 字符。
- 世界观摘要分层归并每批默认最多：5 份。
- LLM 合并失败时使用确定性压缩回退，回退文本默认最多：6000 字符。
- 切分优先使用换行和中英文句末标点，并保证切分段重新拼接后与原文完全一致，不丢失字符。
- 分段大小与归并批量均支持通过 story_planner 环境变量覆盖，预检估算与实际处理共用同一配置。

## 第 4 项验收值

- 默认模型上下文窗口：128000 Token。
- 单次 LLM 输入默认最多：80000 Token；无模型 tokenizer 时按 ASCII、中文和其他 Unicode 字符分类保守估算，emoji/罕见符号预留更多 Token。
- 每次请求固定预留：8000 Token 安全余量，并继续扣除调用阶段原有的 `max_tokens` 输出额度。
- 同步文本、同步 JSON 和异步文本调用统一在 LLM 客户端边界执行预算，覆盖 chapter_branch 全链路并兼容 original。
- system/user prompt 超限时分别保留头部指令和尾部格式约束，中间插入明确裁剪标记；短提示词保持原样。
- 异常大的输出 Token 请求会自动收紧，保证输入、输出与安全余量之和不超过上下文窗口。
- 裁剪日志只记录原始长度、裁剪后长度和预算值，不输出小说正文或 API Key。
- 上下文窗口、最大输入和安全余量均支持通过 story_planner 环境变量覆盖，本地与 K8s 模板使用同一默认值。

## 第 5 项验收值

- LLM 默认最多尝试 5 次（包含首次请求），同步文本、同步 JSON 和异步文本共用统一重试策略。
- 指数退避默认从 2 秒开始、最大 60 秒，并加入最多 20% 随机抖动，避免多个 worker 同时重试形成惊群。
- HTTP 429 优先尊重网关 `Retry-After`；408/409、429、5xx、连接和超时错误可重试。
- 401 鉴权、403 权限、普通 4xx、上下文超限等确定性错误立即失败，不消耗无效重试时间。
- OpenAI SDK 内置重试显式关闭，由 story_planner 统一控制实际尝试次数，避免重试层叠放大流量。
- 每个 worker 进程默认按 60 请求/分钟匀速限流，作为集群共享限流前的第一层保护。
- 每次重试也必须重新获取限流请求槽；异步路径使用异步等待，不阻塞事件循环。
- 日志记录操作名、错误分类、HTTP 状态、尝试次数和等待时间，不输出正文、提示词或 API Key。
- 最大尝试次数、退避参数、抖动比例和每分钟请求数均支持环境变量覆盖，本地与 K8s 模板保持一致。

## 第 6 项验收值

- `chapter_branch_plan` 升级为版本 3，同时保存清洗后原文 SHA-256 与拓扑指纹；原文、拓扑或分支类型变化时废弃旧节点检查点。
- 节点写入采用 `running → persisting → completed` 两阶段落库流程；MD 保存前先记录正文 SHA-256，避免进程在数据库写入与状态更新之间退出后重复调用 LLM。
- 恢复 `persisting` 或新版 `completed` 节点时必须校验数据库 MD 与检查点哈希一致；旧版无哈希的 `completed` 检查点继续兼容。
- 失败任务会把仍处于 `running` 的节点标记为 `failed`，保留错误原因和累计尝试次数，后续运行只重新处理未完成节点。
- 提供 `services.story_planner.tasks.regenerate_chapter_branch_nodes` Celery 入口，支持按一个或多个拓扑节点 ID 定向重生成。
- 定向重生成会自动失效目标节点的非原著下游节点，但在原著收束节点停止扩散；无关的已完成节点继续复用原 MD，不再次调用 LLM。
- 每次定向重生成记录目标节点、原因、请求时间和节点累计重生成次数；未知节点、空节点列表、非 chapter_branch 任务及缺失原文会明确拒绝。

## 第 7 项验收值

- 缓存键由 MD5 升级为 SHA-256，并统一纳入全局命名空间版本、输入全文和阶段参数；提示词、算法或结构发生不兼容变化时通过提升 `STORY_PLANNER_CACHE_VERSION` 整体失效。
- 缓存文件使用带格式版本、命名空间、键和创建时间的 envelope；旧格式、格式版本不匹配、命名空间不匹配、键不匹配、内容损坏和超过 TTL 的数据均不会复用。
- 默认缓存 TTL 为 30 天，可通过 `STORY_PLANNER_CACHE_MAX_AGE_DAYS` 调整；已有按文件年龄清理接口继续保留，用于回收长期未访问的旧版本文件。
- 写入先落临时文件、刷新并 `fsync`，再使用原子替换发布；写入中断不会破坏同键上一份完整缓存，临时文件会自动清理。
- 清空缓存只删除受管理的 `.pkl`/临时文件，不再递归删除整个共享目录，避免误删 PVC 上的其他文件。
- 本地默认目录为 `services/story_planner/.cache/chapter_branch`；K8s 使用已挂载 PVC 下的 `/storage/story_planner/cache/chapter_branch`，10 个副本可复用同一缓存。
- 运行结果记录 namespace、hits、misses、hit rate、writes、invalidations、读写错误和按原因分类的 miss 统计，同时写入 `chapter_branch_plan.metrics` 与最终 `story_tree.json.metrics`。
- 本地与 K8s 环境模板均提供缓存目录、版本和 TTL 配置；K8s LLM 地址仍固定为 `http://172.16.30.31:32691/v1`，模型统一为 `gpt-5.6-sol`。

## 第 8 项验收值

- K8s 通过 Redis 启用集群级 LLM 准入控制；默认整个 story_planner 集群最多 60 请求/分钟，而不是每个 Pod 各自 60 请求/分钟。
- 全局速率采用 Redis 原子 `SET NX PX` 匀速释放请求槽，避免固定窗口边界突发；进程内原有限流继续作为第一层保护。
- 全局在途 LLM 请求默认最多 4 个，10 个 story_planner 副本共同竞争同一组 Redis 并发槽，避免同时压垮中转网关。
- 并发槽使用唯一 token 和 1800 秒租约；正常请求在成功或异常后按 token 原子释放，Pod/进程异常退出时由 TTL 自动回收，不会永久占槽。
- 获取并发槽后再等待速率槽，保证真正发往网关的请求保持全局间隔；等待不会持有 Celery 队列中的额外预取任务。
- 背压默认最多等待 900 秒、每 0.5 秒检查一次；超过上限抛出明确的 `backpressure` 错误，不会无期限占用 worker。
- 同步、异步、文本、JSON 以及每次网络重试都统一经过全局准入，并在请求结束后释放并发槽；异步等待通过线程卸载，不阻塞事件循环。
- Celery 保持每 Pod `concurrency=1`、`prefetch-multiplier=1`，形成 Redis broker 排队、worker 单任务执行、LLM 全局并发/速率控制三层有界背压。
- 本地模板默认关闭 Redis 全局限制，便于单机测试；K8s 模板和 Deployment 默认开启。RPM、并发数、等待时间、轮询间隔和租约均可通过环境变量调整。
